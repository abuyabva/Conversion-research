# Conversion Lab

Агент для исследования конверсии: вопрос и два периода на входе, расчёты воронки и сегментов с журналом вызовов инструментов на выходе.

**C# / .NET 10 · ASP.NET Core · PostgreSQL 17 · Ollama / OpenAI-compatible API · Docker Compose**

Проект решает задачу первичной диагностики: проверить изменение конверсии, найти сегменты со снижением и показать источник каждого числа. Использует синтетический набор интернет-магазина. Не устанавливает причины изменения и не заменяет полноценное продуктовое исследование.

## Как устроено исследование

1. Пользователь задаёт вопрос и подтверждает текущий и базовый периоды в форме.
2. LLM выбирает инструменты и JSON-аргументы: определения метрик, воронку или сравнение сегментов.
3. Сервер проверяет аргументы и выполняет разрешённые операции. При PostgreSQL количества считаются SQL-запросами, проценты — в C#.
4. Результаты возвращаются модели для продолжения исследования.
5. Итоговые наблюдения формируются сервером из успешных результатов инструментов. Свободный текст модели не используется как источник фактов.

В интерфейсе доступны текстовый отчёт, таблицы и журнал с аргументами, результатами и длительностью инструментов.

### Почему факты формируются кодом

При проверке Qwen2.5 3B модель корректно вызвала инструменты, но приписала падение конверсии не тому сегменту. Поэтому выбор действий оставлен модели, а отображение чисел и сегментов сделано детерминированным. Это ограничение свободы вывода, а не универсальная проверка достоверности LLM. Тесты защищают соответствие отчёта результатам инструментов.

Модель может завершить исследование, не запросив все нужные разрезы. `complete` означает завершение цикла с полученными аналитическими данными, но не полноту ответа на любой вопрос. Если в журнале нет `compare_segments`, сегментный вывод не сделан. Для проверки сегментов задайте явный вопрос о сравнении устройства и источника трафика.

## Быстрый старт: без модели и базы

Нужен .NET 10 SDK. Из корня репозитория:

```powershell
dotnet run --project src/ConversionAgent --urls http://localhost:5187
```

Откройте http://localhost:5187, подставьте демонстрационные периоды и запустите исследование. Значения по умолчанию — Demo / Synthetic. Demo выполняет фиксированный сценарий и не интерпретирует свободный вопрос.

## Docker и PostgreSQL

Нужен Docker Desktop с Linux-контейнерами. Если `.env` ещё не существует:

```powershell
Copy-Item .env.example .env
```

Не перезаписывайте имеющийся `.env`. Запуск:

```powershell
docker compose up --build -d
```

Интерфейс: http://localhost:8080. По умолчанию Compose запускает Demo / Postgres. `db/init.sql` создаёт и заполняет базу при первом запуске на пустом томе.

```powershell
docker compose down
```

Эта команда сохраняет данные. Для изменения исходного набора недостаточно перезапустить контейнер: инициализация уже существующей базы повторно не выполняется.

## Локальная LLM: Ollama

Проверенная в ручном сценарии модель — `qwen2.5:3b`, запуск на Windows с CPU. Скорость зависит от устройства; многошаговый запрос может занимать несколько минут.

```powershell
ollama pull qwen2.5:3b
```

Оставьте Ollama запущенной. Для приложения в Docker задайте в `.env`:

```dotenv
AGENT_MODE=Llm
LLM_PROVIDER=Ollama
LLM_BASE_URL=http://host.docker.internal:11434/v1/
LLM_MODEL=qwen2.5:3b
LLM_API_KEY=ollama
```

Пароль PostgreSQL оставьте прежним. Значение `ollama` — заглушка, локальный клиент не отправляет его как авторизацию.

```powershell
docker compose up -d --force-recreate app
```

При запуске приложения непосредственно на Windows вместо Docker адрес модели — `http://localhost:11434/v1/`. Обычный `dotnet run` не читает `.env`: настройки задаются через `Llm__BaseUrl`, `Llm__Model`, `Llm__Provider`, `Agent__Mode` и другие переменные окружения .NET.

Если контейнер не видит Ollama, сначала проверьте Windows API:

```powershell
(Invoke-RestMethod 'http://localhost:11434/v1/models').data.id
```

Для временной диагностики завершите Ollama через системный трей и в отдельном PowerShell запустите:

```powershell
$env:OLLAMA_HOST='0.0.0.0:11434'
ollama serve
```

Это открывает прослушивание сетевых интерфейсов. Не публикуйте порт 11434 в интернет и не отключайте брандмауэр. Остановка — Ctrl+C.

## Другой провайдер

Клиент поддерживает формат Chat Completions с function calling. Пример настройки:

```dotenv
AGENT_MODE=Llm
LLM_PROVIDER=OpenAI
LLM_BASE_URL=https://api.openai.com/v1/
LLM_MODEL=gpt-4.1-mini
LLM_API_KEY=YOUR_API_KEY
```

Доступность и стоимость зависят от аккаунта провайдера. Совместимый формат не гарантирует совместимость каждой модели: многошаговые вызовы инструментов нужно проверять отдельно. Ключ хранится только на сервере.

`LLM_PROVIDER=Auto` распознаёт локальную Ollama на порту 11434. Для нестандартных адресов выбирайте провайдер явно.

## Контрольный набор

Периоды в UTC, конец не включается: базовый `[2026-10-05, 2026-10-12)`, текущий `[2026-10-12, 2026-10-19)`.

| Показатель | Базовый | Текущий |
|---|---:|---:|
| Посетители | 2800 | 2800 |
| Дошли до checkout | 1680 | 1470 |
| Оплатили | 1120 | 910 |
| Конверсия в оплату | 40% | 32,5% |
| Конверсия mobile/paid | 40% | 10% |

Конверсия — уникальные оплатившие / посетители × 100. Нулевой знаменатель даёт `null`. Общее изменение составляет −7,5 п.п.; в mobile/paid — −30 п.п. Остальные пересечения не меняются. Наибольшее падение доли не обязательно означает наибольший вклад в общий результат.

Это заданный синтетический сценарий, не измеренный эффект реального продукта.

## Проверки

```powershell
dotnet run --project tests/ConversionAgent.Tests
```

Тестовый проект — консольный стенд без xUnit; запускается через `dotnet run`. 41 автоматическая проверка покрывает расчёты, даты, ошибки инструментов, HTTP-контракт и формирование отчёта.

Дополнительная проверка PostgreSQL (подставьте пароль своей тестовой базы):

```powershell
$env:TEST_POSTGRES='Host=127.0.0.1;Port=54329;Database=conversion;Username=demo;Password=YOUR_TEST_PASSWORD'

```

Это добавляет 12 сравнений PostgreSQL и встроенного набора. Без `TEST_POSTGRES` они явно пропускаются. CI описан в `.github/workflows/ci.yml`; успешность запуска проверяется в Actions после публикации.

## Ограничения

- Синтетические данные: один визит на пользователя, упрощённая воронка. Граница периода может отсечь позднюю покупку; это не когорта с одинаковым окном созревания.
- Даты задаются в форме. Нет памяти диалога, RAG или доступа к произвольному SQL.
- Нет гарантии полноты выбора инструментов моделью. Неопределённая конверсия не заменяется нулём; отсутствующие расчёты не выдумываются.
- Максимум 8 обращений к модели и 12 инструментов. По умолчанию Ollama: 180 секунд на обращение, 600 на исследование; OpenAI: 40 и 120 секунд. Браузер ждёт на 5 секунд дольше общего лимита.
- Нет проверки причинности, статистической значимости и бизнес-эффекта. Рекомендации о следующих проверках общие, причины не установлены.
- Приложение рассчитано на локальную демонстрацию. Для публичного размещения нужны аутентификация, отдельные роли БД, контроль расходов и нагрузочная проверка.
